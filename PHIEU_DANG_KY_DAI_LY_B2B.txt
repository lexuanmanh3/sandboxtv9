1. NGUYÊN TẮC BẢO MẬT & HEADERS BẮT BUỘC
--------------------------------------------------------------------------------
Tất cả các API nghiệp vụ đều được bảo vệ bởi IP Whitelist và Chữ ký điện tử HMAC-SHA256.
Mỗi request gửi sang hệ thống B2B phải có đủ 5 HTTP Headers sau:

+--------------------+---------------+------------------------------------------+
| Tên Header         | Kiểu dữ liệu  | Ý nghĩa & Quy cách                       |
+--------------------+---------------+------------------------------------------+
| X-Client-Id        | Chuỗi         | Client ID do TV9 cấp                     |
| X-Timestamp        | Số nguyên     | Unix timestamp hiện tại (giây).          |
|                    |               | Sai lệch tối đa cho phép: +/- 300 giây   |
| X-Nonce            | Chuỗi         | Chuỗi ngẫu nhiên (tối thiểu 16 ký tự).   |
|                    |               | Chống tấn công lặp lại (Replay Attack)   |
| X-Signature        | Chuỗi         | Chữ ký HMAC SHA-256 (64 ký tự hex thường)|
| Idempotency-Key    | Chuỗi (UUID)  | UUID v4 duy nhất cho mỗi đơn hàng.       |
|                    |               | BẮT BUỘC đối với request POST/PUT        |
| Content-Type       | Chuỗi         | application/json (với POST/PUT)          |
+--------------------+---------------+------------------------------------------+


2. THUẬT TOÁN TẠO CHỮ KÝ SỐ (CANONICAL STRING 6 DÒNG)
--------------------------------------------------------------------------------
Chuỗi Canonical String được ghép chính xác từ 6 dòng, phân tách bởi ký tự xuống 
dòng '\n' (0x0A):

---------------------------------
METHOD
CANONICAL_PATH_WITH_QUERY
TIMESTAMP
NONCE
IDEMPOTENCY_KEY
BODY_SHA256
---------------------------------

Quy tắc chi tiết:
- Dòng 1 (METHOD): Viết hoa phương thức HTTP (GET, POST, PUT, DELETE).
- Dòng 2 (CANONICAL_PATH_WITH_QUERY): Đường dẫn URI (VD: /api/b2b/v1/orders).
- Dòng 3 (TIMESTAMP): Giá trị nguyên của X-Timestamp.
- Dòng 4 (NONCE): Giá trị nguyên gốc của X-Nonce.
- Dòng 5 (IDEMPOTENCY_KEY): Giá trị Idempotency-Key. (Nếu là GET, để trống dòng này).
- Dòng 6 (BODY_SHA256): Chuỗi hex hash SHA-256 của Raw JSON Body. 
  Nếu không có Body (như GET), hash của chuỗi rỗng '': 
  e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

Chữ ký tạo bởi:
  Signature = hash_hmac('sha256', Canonical_String, Secret_Key)

4. MÃ NGUỒN MẪU TẠO ĐƠN NẠP TIỀN BẰNG PHP
--------------------------------------------------------------------------------
<?php
$clientId = 'YOUR_CLIENT_ID';
$clientSecret = 'YOUR_SECRET_KEY';
$baseUrl = 'https://sandboxtv9.online/api/b2b/v1';

$path = '/api/b2b/v1/orders';
$timestamp = time();
$nonce = bin2hex(random_bytes(16));
$idempotencyKey = sprintf('%04x%04x-%04x-%04x-%04x-%04x%04x%04x',
    mt_rand(0, 0xffff), mt_rand(0, 0xffff), mt_rand(0, 0xffff),
    mt_rand(0, 0x0fff) | 0x4000, mt_rand(0, 0x3fff) | 0x8000,
    mt_rand(0, 0xffff), mt_rand(0, 0xffff), mt_rand(0, 0xffff)
);

$payload = [
    'partner_order_id' => 'ORD_' . time(),
    'product_code' => 'TOPUP_VTE_10K',
    'account' => '0965657810',
];
$bodyJson = json_encode($payload, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE);
$bodySha256 = hash('sha256', $bodyJson);

$canonical = implode("\n", [
    'POST',
    $path,
    $timestamp,
    $nonce,
    $idempotencyKey,
    $bodySha256
]);
$signature = hash_hmac('sha256', $canonical, $clientSecret);

$ch = curl_init($baseUrl . '/orders');
curl_setopt_array($ch, [
    CURLOPT_POST => true,
    CURLOPT_POSTFIELDS => $bodyJson,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        'Content-Type: application/json',
        'X-Client-Id: ' . $clientId,
        'X-Timestamp: ' . $timestamp,
        'X-Nonce: ' . $nonce,
        'X-Signature: ' . $signature,
        'Idempotency-Key: ' . $idempotencyKey,
    ],
]);
$response = curl_exec($ch);
$httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
curl_close($ch);

echo "HTTP Code: $httpCode\n";
echo "Response: $response\n";
?>

6. QUY ĐỊNH AN TOÀN KHI XỬ LÝ LỖI MẠNG & RETRY (IDEMPOTENCY)
--------------------------------------------------------------------------------
- Khi đối tác gọi API bị TIMEOUT hoặc LỖI MẠNG (không nhận được response):
  => BẮT BUỘC gửi lại (Retry) với NGUYÊN VẸN Idempotency-Key và partner_order_id cũ.
  => Hệ thống TV9 sẽ trả lại kết quả đơn hàng đã tạo an toàn, TUYỆT ĐỐI không trừ tiền 
     hai lần và không tạo đơn trùng lặp.
- TUYỆT ĐỐI KHÔNG tự động đổi partner_order_id mới để nạp lại khi đơn cũ chưa có kết quả 
  thất bại rõ ràng.
- Đơn hàng ở trạng thái "manual_review": Nhà mạng đang xử lý chậm hoặc nghẽn mạng, 
  hệ thống đang bảo toàn giao dịch. Đối tác KHÔNG hoàn tiền cho khách và KHÔNG nạp lại.


7. CƠ CHẾ NHẬN WEBHOOK KẾT QUẢ ĐƠN HÀNG
--------------------------------------------------------------------------------
Khi giao dịch nạp tiền hoàn tất trên nhà mạng, hệ thống TV9 sẽ tự động gửi 
HTTP POST Webhook đến "URL nhận Webhook" do đối tác đã đăng ký:

Headers Webhook:
  Content-Type: application/json
  X-Signature: [Chữ ký HMAC SHA-256 tính từ Webhook Payload bằng Secret Key]

Payload JSON Webhook:
{
    "event_id": "c1f72a44-8d4e-5c79-b1d3-3a5f8b91a022",
    "event_type": "order.completed",
    "partner_order_id": "DH_20260919_001",
    "order_id": 1045,
    "status": "success",
    "product_code": "TOPUP_VTE_10K",
    "account": "0965657810",
    "amount": 10000,
    "completed_at": "2026-09-19T02:15:05+07:00"
}

Đối tác xác thực chữ ký Webhook:
  $calculatedSig = hash_hmac('sha256', $rawPayloadJson, $clientSecret);
  Nếu $calculatedSig == $_SERVER['HTTP_X_SIGNATURE'] => Hợp lệ.
  Đối tác trả về HTTP 200 {"received": true} để xác nhận đã tiếp nhận thành công.

9. BẢNG MÃ TRẠNG THÁI & MÃ LỖI THƯỜNG GẶP
--------------------------------------------------------------------------------
Trạng thái đơn hàng (status):
- pending:        Đã nhận đơn, đang chờ worker xử lý.
- processing:     Đang thực hiện giao dịch sang nhà mạng.
- success:        Nạp tiền thành công.
- failed:         Nạp tiền thất bại (được phép hoàn tiền/nạp lại).
- manual_review:  Treo giao dịch nhà mạng, chờ đối soát kỹ thuật (không nạp lại).

Mã lỗi HTTP phổ biến:
- 400 MISSING_HEADERS:         Thiếu một trong 4 headers bắt buộc.
- 400 MISSING_IDEMPOTENCY_KEY: Thiếu header Idempotency-Key khi tạo đơn.
- 401 INVALID_SIGNATURE:       Chữ ký X-Signature không khớp.
- 401 REQUEST_EXPIRED:         Timestamp sai lệch quá 300 giây so với giờ server.
- 401 REPLAY_DETECTED:         X-Nonce đã được sử dụng trong vòng 10 phút qua.
- 403 IP_NOT_ALLOWED:          IP gọi không nằm trong danh sách IP Whitelist.
- 404 PRODUCT_NOT_FOUND:       Mã product_code không tồn tại.
- 409 DUPLICATE_ORDER:         partner_order_id đã tồn tại nhưng gửi kèm key khác.
- 409 IDEMPOTENCY_CONFLICT:    Gửi lại Idempotency-Key cũ nhưng đổi nội dung đơn.
- 422 INSUFFICIENT_CREDIT:     Hạn mức khả dụng không đủ để tạo đơn.
